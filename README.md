# 羽球记

羽毛球群的比赛记录与个人排名网页实验版。独立于微信小程序，不需要微信 AppID。

## 功能

- 男单、男双、混双；15/21分，逐局添加，任意局数提交，支持平局。
- 草稿暂存与恢复；输入较低得分后自动补另一侧，已填值不覆盖。
- 群邀请码加入，球友名字认领由管理员审核，无需邮箱或手机号注册。
- 每次提交开始24小时异议期；对方可确认或提出异议。
- 临时队员可以出场，正式队员正常计分，临时队员不累计个人积分。
- 综合与分项目实力排名、季度积分、历史修正与操作记录。
- 个人登录码用于换手机恢复身份；请只保存给自己。

## 本地运行

使用 Node.js 22.16+，无需安装依赖：

```sh
npm test
npm run dev
```

打开 `http://127.0.0.1:4174/`。本机数据库保存在 `.local/web.sqlite`，不进入 Git 仓库。

## 公网体验页

访问 [羽球记网页体验](https://liushoucheng.github.io/yuqiuji/)。已通过 HTTP200 和浏览器首页检查，无需登录 GitHub。

GitHub Pages 体验页使用 `docs/`，由 `npm run build:pages` 生成。体验页数据仅保存在当前浏览器，默认球友和历史比赛均为虚构；在「我的」中切换体验身份可模拟对方确认。它不能用于群成员之间自动同步，页面顶部始终显示这个限制。

共享版仍使用 `site/` 中的服务端实现，以下说明针对共享版。

## 共享版托管

`npm run build` 生成 `dist/server/index.js`，是包含所有页面资源的 Cloudflare Worker ESM，默认导出 `fetch`。需要名为 `DB` 的 D1 绑定。首次部署前通过平台迁移工具执行 `drizzle/0000_court.sql`；不要在请求处理时创建表。

后端从 HttpOnly Cookie 验证随机身份，服务端审核成员权限；客户端提交的管理员标志和球员身份不会作为授权依据。文档版本阻止并发覆盖，提交标识避免网络重试新增重复比赛。

GitHub Pages 只能托管静态页面，不能直接运行这个共享后端。共享版也可部署到独立 Linux 服务器，使用相同业务代码和 Node 自带 SQLite。

## 阿里云服务器运行

服务器需要 Node.js 22.16+。不需要 npm install。先执行 `npm test`，再运行：

```sh
HOST=127.0.0.1 PORT=8081 \
PUBLIC_ORIGIN=https://你的域名:8443 \
DATABASE_PATH=/持久数据目录/web.sqlite \
TRUST_PROXY=1 npm start
```

`PUBLIC_ORIGIN` 必须与用户访问的完整网址一致，含协议和非默认端口；不能取客户端 Host 或转发头。`TRUST_PROXY=1` 只允许监听本机，并由 HTTPS 代理设置真实来源 IP。请求超过64KB会在缓冲时拒绝。

`deploy/` 中提供针对当前韩国服务器的 systemd 和 Caddy 配置：应用监听 `127.0.0.1:8081`，网页 HTTPS 使用8443；80仅供证书验证和跳转，现有VPN的443不改动。临时网址为 `https://yuqiuji-8-220-213-28.sslip.io:8443/`。2026-10-12已安装Node22.23.3与Caddy2.11.7，两个服务均启用；服务器侧的共享流程、数据重启保存和可信HTTPS证书通过。当前8443外网连接仍未通过，待确认阿里云入站规则后再验证公网可用性。

应用位于 `/opt/yuqiuji/app`，运行环境位于 `/opt/yuqiuji/runtime`；SQLite 数据持久保存在 `/var/lib/yuqiuji/web.sqlite`，证书保存在 `/var/lib/yuqiuji-caddy`，都不进入源码仓库。两个服务通过 systemd 自动启动，以独立动态用户运行。首次新数据库自动应用 `drizzle/0000_court.sql`；已有数据库和身份在重启后保留。

上线前需放行阿里云安全组TCP80、8443，并完成可信证书和外网访问验证。首次创建真实战绩簿的浏览器成为管理员，应自行保存个人登录码。

服务器在读取或修改时结算已到24小时期限的比赛；没有独立后台定时任务。最多100位球友、150个身份、500场比赛及800KB战绩文档，达到容量时拒绝新写入，保留历史。

实力算法尚未用真实群内成绩校准；平局每人+1参与积分、实力不变，排名仅供球友交流参考。
